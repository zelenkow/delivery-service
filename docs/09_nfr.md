# Нефункциональные требования (NFR) — Микросервис доставки посылок


## 1. Производительность

| ID | Требование | Значение |
|----|-----------|----------|
| NFR-PERF-01 | Время ответа API (p95) для CRUD-операций | ≤ 300 мс |
| NFR-PERF-02 | Время ответа RAG-эндпоинта (p95) | ≤ 5 с |
| NFR-PERF-03 | Пропускная способность | ≥ 100 RPS на CRUD |
| NFR-PERF-04 | Обработка периодической задачи | до 10 000 посылок за запуск |
| NFR-PERF-05 | Агрегация отчёта по 1 млн записей | ≤ 3 с |

## 2. Масштабируемость

| ID | Требование |
|----|-----------|
| NFR-SCALE-01 | Горизонтальное масштабирование web-сервиса (stateless, сессия в БД/Redis) |
| NFR-SCALE-02 | Возможность масштабирования воркеров Celery |
| NFR-SCALE-03 | Поддержка до 1 млн посылок в день (доп. задание) |

## 3. Надёжность и отказоустойчивость

| ID | Требование |
|----|-----------|
| NFR-REL-01 | При недоступности API ЦБ РФ используется последнее кешированное значение курса |
| NFR-REL-02 | При недоступности LLM возвращается стандартизированная ошибка 502/504 |
| NFR-REL-03 | При недоступности векторной БД возвращается 503 |
| NFR-REL-04 | Сообщения RabbitMQ при ошибке уходят в DLQ |
| NFR-REL-05 | Атомарность привязки посылки к компании (защита от гонки) |

## 4. Кеширование

| ID | Требование |
|----|-----------|
| NFR-CACHE-01 | Курс USD/RUB кешируется в Redis |
| NFR-CACHE-02 | TTL кеша курса — 1 час |
| NFR-CACHE-03 | При промахе кеша — запрос к внешнему API |

## 5. Логирование

| ID | Требование |
|----|-----------|
| NFR-LOG-01 | Логирование всех HTTP-запросов (метод, путь, статус, длительность, session_key) |
| NFR-LOG-02 | Логирование ошибок с трассировкой |
| NFR-LOG-03 | Логирование результатов периодических задач |
| NFR-LOG-04 | Структурированный формат логов (JSON) |
| NFR-LOG-05 | Уровни логирования: DEBUG (dev), INFO (prod) |

## 6. Безопасность

| ID | Требование |
|----|-----------|
| NFR-SEC-01 | Авторизация отсутствует (требование задания) |
| NFR-SEC-02 | Изоляция данных по сессии: пользователь видит только свои посылки |
| NFR-SEC-03 | Валидация всех входных данных |
| NFR-SEC-04 | Защита от SQL-инъекций (ORM Django) |
| NFR-SEC-05 | Секреты (ключи LLM, пароли БД) — через переменные окружения |
| NFR-SEC-06 | CSRF-защита для небезопасных методов (при необходимости) |

## 7. Стандартизация ответов и ошибок

| ID | Требование |
|----|-----------|
| NFR-API-01 | Единый формат успешного ответа: `{data, meta}` |
| NFR-API-02 | Единый формат ошибки: `{error: {code, message, details}}` |
| NFR-API-03 | Использование корректных HTTP-статусов |
| NFR-API-04 | Документирование всех эндпоинтов через Swagger/OpenAPI |

## 8. Совместимость и стандарты

| ID | Требование |
|----|-----------|
| NFR-STD-01 | Python 3.14 |
| NFR-STD-02 | Следование PEP 8, линтер Ruff |
| NFR-STD-03 | Типизация, проверка mypy (strict) |
| NFR-STD-04 | Документирование основных методов (docstrings) |
| NFR-STD-05 | Покрытие тестами (плюс) |

## 9. Развёртывание

| ID | Требование |
|----|-----------|
| NFR-DEP-01 | Докеризация всех компонентов |
| NFR-DEP-02 | Запуск одной командой `docker-compose up` |
| NFR-DEP-03 | Миграции БД применяются автоматически при старте |
| NFR-DEP-04 | Seed-данные типов посылок загружаются при инициализации |

## 10. Поддерживаемость

| ID | Требование |
|----|-----------|
| NFR-MAINT-01 | Модульная структура (разделение по приложениям) |
| NFR-MAINT-02 | Чистота и понятность кода |
| NFR-MAINT-03 | Конфигурация через переменные окружения |
| NFR-MAINT-04 | Документирование обоснований решений (при затруднениях) |

## 11. RAG-специфичные требования

| ID | Требование |
|----|-----------|
| NFR-RAG-01 | База знаний загружается и векторизуется заранее (offline) |
| NFR-RAG-02 | Размер чанка — ~500 токенов с перекрытием |
| NFR-RAG-03 | Top-K поиска — 5 фрагментов |
| NFR-RAG-04 | LLM отвечает только на основе найденного контекста |
| NFR-RAG-05 | При отсутствии релевантного контекста LLM сообщает о незнании |

## 12. Ограничения

| ID | Ограничение |
|----|-------------|
| NFR-CONST-01 | Приложение НЕ содержит авторизации |
| NFR-CONST-02 | Данные хранятся в PostgreSQL/MySQL |
| NFR-CONST-03 | Векторная БД — Qdrant или ChromaDB |
| NFR-CONST-04 | Реализация на Django или FastAPI |
| NFR-CONST-05 | Описание API через Swagger |
