# Глоссарий проекта — Микросервис доставки посылок


## Бизнес-термины

| Термин | Определение |
|--------|-------------|
| **Посылка (Parcel)** | Отправление, зарегистрированное пользователем. Характеризуется названием, весом, типом и стоимостью содержимого. |
| **Тип посылки (Parcel Type)** | Категория отправления. В системе три типа: `одежда`, `электроника`, `разное`. Хранится в отдельной таблице БД. |
| **Стоимость содержимого** | Заявленная стоимость вложений в посылку, выраженная в долларах США (`content_cost_usd`). |
| **Стоимость доставки** | Рассчитанная стоимость пересылки посылки в рублях. Вычисляется по формуле и хранится в БД. |
| **Курс USD/RUB** | Актуальный курс доллара к рублю, получаемый из внешнего API ЦБ РФ. |
| **Не рассчитано** | Текстовый статус, отображаемый вместо стоимости доставки, если она ещё не вычислена. |
| **Служба поддержки (RAG)** | Виртуальный ассистент, отвечающий на вопросы пользователей на основе базы знаний и LLM. |
| **База знаний** | Фиктивный текстовый файл с правилами таможни и доставки, используемый для RAG-поиска. |
| **Транспортная компания** | Внешний контрагент, который может закрепить посылку за собой для доставки (доп. задание). |

## Технические термины

| Термин | Определение |
|--------|-------------|
| **Сессия (Session)** | Механизм идентификации пользователя без авторизации. Каждому пользователю соответствует свой набор посылок. |
| **Middleware** | Промежуточный слой обработки запросов в Django, используемый для работы с сессиями и логированием. |
| **RAG (Retrieval-Augmented Generation)** | Архитектура, при которой LLM генерирует ответ с опорой на найденный в базе знаний контекст. |
| **Векторизация (Embedding)** | Преобразование текста в числовой вектор для поиска по смыслу. |
| **Векторная БД** | База данных для хранения и поиска векторов. Рекомендуется Qdrant или ChromaDB. |
| **LLM (Large Language Model)** | Большая языковая модель, генерирующая ответы. Может быть внешней (OpenAI, YandexGPT, GigaChat) или локальной. |
| **Кеш (Cache)** | Быстрое хранилище часто запрашиваемых данных. В проекте используется Redis для кеширования курса валют. |
| **Redis** | In-memory хранилище «ключ-значение», используемое для кеша. |
| **Периодическая задача (Scheduled Task)** | Задача, выполняемая по расписанию. В проекте — расчёт стоимости доставки раз в 5 минут. |
| **Планировщик (Scheduler)** | Компонент, запускающий периодические задачи (например, Celery Beat). |
| **Брокер сообщений** | Промежуточный компонент для асинхронной передачи сообщений (RabbitMQ). |
| **Воркер (Worker)** | Процесс, обрабатывающий сообщения из очереди. |
| **DLQ (Dead Letter Queue)** | Очередь для сообщений, которые не удалось обработать. |
| **Гонка транзакций (Race Condition)** | Ситуация, когда параллельные запросы конкурируют за один ресурс. Решается атомарными операциями. |
| **Атомарное обновление** | Операция БД, выполняемая целиком и неделимо (например, `UPDATE ... WHERE company_id IS NULL`). |
| **Пагинация (Pagination)** | Постраничный вывод списка записей. |
| **Фильтрация (Filtering)** | Отбор записей по заданным условиям. |
| **Swagger / OpenAPI** | Спецификация и интерактивная документация REST API. |
| **Docker Compose** | Инструмент запуска многоконтейнерного приложения одной командой. |
| **MongoDB** | Документоориентированная БД, используемая для хранения лога расчётов (доп. задание). |

## Формулы

**Стоимость доставки:**

```
delivery_cost = (weight_kg * 0.5 + content_cost_usd * 0.01) * usd_rub_rate
```

где:
- `weight_kg` — вес посылки в килограммах;
- `content_cost_usd` — стоимость содержимого в долларах;
- `usd_rub_rate` — курс доллара к рублю.
