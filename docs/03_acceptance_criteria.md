# Acceptance Criteria — Микросервис доставки посылок


## Формат

Критерии приёмки записаны в формате **Given / When / Then** (Gherkin-подобный).
Каждый блок соответствует User Story из [`01_user_stories.md`](01_user_stories.md).

---

## AC-01. Регистрация посылки (US-01)

**AC-01.1 — Успешная регистрация**
- **Given** активная сессия пользователя и валидные данные посылки,
- **When** пользователь отправляет `POST /api/parcels/` с JSON,
- **Then** возвращается `201 Created` и уникальный `id` посылки.

**AC-01.2 — Валидация обязательных полей**
- **Given** отсутствует одно из полей `name`, `weight`, `type`, `content_cost_usd`,
- **When** отправлен запрос,
- **Then** возвращается `400 Bad Request` с указанием отсутствующего поля.

**AC-01.3 — Валидация веса**
- **Given** `weight <= 0`,
- **When** отправлен запрос,
- **Then** возвращается `400 Bad Request`.

**AC-01.4 — Валидация стоимости содержимого**
- **Given** `content_cost_usd < 0`,
- **When** отправлен запрос,
- **Then** возвращается `400 Bad Request`.

**AC-01.5 — Валидация типа**
- **Given** `type` не существует в справочнике типов,
- **When** отправлен запрос,
- **Then** возвращается `400 Bad Request`.

**AC-01.6 — Изоляция по сессии**
- **Given** посылка создана в сессии A,
- **When** сессия B запрашивает эту посылку,
- **Then** возвращается `404 Not Found`.

## AC-02. Справочник типов (US-02)

**AC-02.1 — Получение типов**
- **Given** в БД есть 3 типа,
- **When** пользователь отправляет `GET /api/parcel-types/`,
- **Then** возвращается `200 OK` и список из 3 элементов с `id` и `name`.

**AC-02.2 — Состав типов**
- **Given** сервис инициализирован,
- **When** запрошен справочник,
- **Then** присутствуют типы `одежда`, `электроника`, `разное`.

**AC-02.3 — Хранение в отдельной таблице**
- **Given** схема БД,
- **When** выполняется миграция,
- **Then** существует отдельная таблица типов посылок.

---

## AC-03. Список своих посылок (US-03)

**AC-03.1 — Только свои посылки**
- **Given** в сессии A 5 посылок, в сессии B 3 посылки,
- **When** сессия A запрашивает список,
- **Then** возвращаются только 5 посылок сессии A.

**AC-03.2 — Пагинация**
- **Given** 25 посылок в сессии,
- **When** запрошена страница `page=2&page_size=10`,
- **Then** возвращается 10 записей и метаданные пагинации (total, page, page_size).

**AC-03.3 — Фильтр по типу**
- **Given** посылки разных типов,
- **When** передан `type=<id>`,
- **Then** возвращаются только посылки этого типа.

**AC-03.4 — Фильтр по наличию стоимости**
- **Given** часть посылок без стоимости,
- **When** передан `has_delivery_cost=false`,
- **Then** возвращаются только посылки без рассчитанной стоимости.

**AC-03.5 — Поле имени типа**
- **Given** посылка с типом,
- **When** запрошен список,
- **Then** в каждой записи присутствует имя типа (не только id).

**AC-03.6 — Статус «Не рассчитано»**
- **Given** посылка без рассчитанной стоимости,
- **When** запрошен список,
- **Then** в поле `delivery_cost` возвращается «Не рассчитано».

## AC-04. Данные о посылке по id (US-04)

**AC-04.1 — Успешное получение**
- **Given** посылка принадлежит текущей сессии,
- **When** отправлен `GET /api/parcels/{id}/`,
- **Then** возвращается `200 OK` с полями `name`, `weight`, `type`, `content_cost_usd`, `delivery_cost`.

**AC-04.2 — Не найдено**
- **Given** посылки с таким `id` нет,
- **When** отправлен запрос,
- **Then** возвращается `404 Not Found`.

**AC-04.3 — Чужая посылка**
- **Given** посылка принадлежит другой сессии,
- **When** отправлен запрос,
- **Then** возвращается `404 Not Found`.

## AC-05. RAG-вопрос поддержке (US-05)

**AC-05.1 — Успешный ответ**
- **Given** база знаний загружена в векторную БД,
- **When** пользователь отправляет `POST /api/support/ask/` с вопросом,
- **Then** возвращается `200 OK` с текстом ответа.

**AC-05.2 — Валидация вопроса**
- **Given** пустой вопрос,
- **When** отправлен запрос,
- **Then** возвращается `400 Bad Request`.

**AC-05.3 — Векторный поиск**
- **Given** вопрос релевантен базе знаний,
- **When** выполняется поиск,
- **Then** из векторной БД извлекается top-K релевантных фрагментов.

**AC-05.4 — Передача контекста в LLM**
- **Given** найден контекст,
- **When** формируется запрос к LLM,
- **Then** контекст включён в промпт.

**AC-05.5 — Недоступность LLM**
- **Given** LLM API недоступна,
- **When** отправлен вопрос,
- **Then** возвращается `502`/`504` со стандартизированной ошибкой.

**AC-05.6 — Недоступность векторной БД**
- **Given** Qdrant/ChromaDB недоступна,
- **When** отправлен вопрос,
- **Then** возвращается `503 Service Unavailable`.

## AC-06. Авторасчёт стоимости (US-06)

**AC-06.1 — Периодичность**
- **Given** сервис запущен,
- **When** проходит 5 минут,
- **Then** задача расчёта запускается автоматически.

**AC-06.2 — Формула расчёта**
- **Given** посылка с `weight=2`, `content_cost_usd=100`, курс `rate=90`,
- **When** выполняется расчёт,
- **Then** `delivery_cost = (2*0.5 + 100*0.01) * 90 = (1 + 1) * 90 = 180`.

**AC-06.3 — Только необработанные**
- **Given** часть посылок уже имеет стоимость,
- **When** выполняется задача,
- **Then** обрабатываются только посылки с `delivery_cost IS NULL`.

**AC-06.4 — Кеширование курса в Redis**
- **Given** курс получен,
- **When** задача запускается повторно,
- **Then** курс берётся из Redis, а не из внешнего API.

**AC-06.5 — Источник курса**
- **Given** кеш пуст,
- **When** задача запускается,
- **Then** курс запрашивается с `https://www.cbr-xml-daily.ru/daily_json.js`.

## AC-07. Ручной запуск задачи (US-07)

**AC-07.1 — Запуск вне расписания**
- **Given** сервис запущен,
- **When** разработчик запускает команду расчёта,
- **Then** задача выполняется немедленно.

**AC-07.2 — Отчёт**
- **Given** задача выполнена,
- **When** она завершается,
- **Then** в консоль выводится количество обработанных посылок.

---

## AC-08. Статус «Не рассчитано» (US-08)

**AC-08.1 — Отображение статуса**
- **Given** `delivery_cost IS NULL`,
- **When** данные посылки возвращаются пользователю,
- **Then** в поле стоимости выводится «Не рассчитано».

---

## AC-09. Привязка к транспортной компании (US-09)

**AC-09.1 — Успешная привязка**
- **Given** посылка не привязана,
- **When** компания отправляет `POST /api/parcels/{id}/assign/` с `company_id`,
- **Then** возвращается `200 OK`, посылка закреплена за компанией.

**AC-09.2 — Гарантия первой компании**
- **Given** две компании одновременно отправляют запрос,
- **When** оба запроса обрабатываются,
- **Then** успешен только один, второй получает `409 Conflict`.

**AC-09.3 — Валидация company_id**
- **Given** `company_id <= 0`,
- **When** отправлен запрос,
- **Then** возвращается `400 Bad Request`.

**AC-09.4 — Атомарность**
- **Given** высокая нагрузка (несколько запросов в секунду),
- **When** запросы приходят параллельно,
- **Then** гарантируется отсутствие двойной привязки (атомарный UPDATE с условием).

---

## AC-10. Регистрация через RabbitMQ (US-10)

**AC-10.1 — Публикация в очередь**
- **Given** валидные данные,
- **When** пользователь отправляет `POST /api/parcels/`,
- **Then** сообщение публикуется в RabbitMQ, возвращается `202 Accepted`.

**AC-10.2 — Обработка воркером**
- **Given** сообщение в очереди,
- **When** воркер его получает,
- **Then** посылка сохраняется в БД и стоимость рассчитывается сразу.

**AC-10.3 — Отказ от периодической задачи**
- **Given** включён режим RabbitMQ,
- **When** сервис работает,
- **Then** периодическая задача расчёта не запускается.

**AC-10.4 — Обработка ошибок**
- **Given** воркер не смог обработать сообщение,
- **When** исчерпаны ретраи,
- **Then** сообщение попадает в DLQ и логируется.

---

## AC-11. Подсчёт сумм по типам за день (US-11)

**AC-11.1 — Агрегация**
- **Given** лог расчётов в MongoDB за день,
- **When** запрошен отчёт,
- **Then** возвращается сумма стоимостей по каждому типу.

**AC-11.2 — Производительность**
- **Given** до 1 млн записей в день,
- **When** выполняется агрегация,
- **Then** используется индексированный pipeline MongoDB.

## Общие критерии (сквозные)

**AC-COMMON.1 — Стандартизация ошибок**
- **Given** любая ошибка,
- **When** формируется ответ,
- **Then** ответ имеет единый формат (код, сообщение, детали).

**AC-COMMON.2 — Логирование**
- **Given** обработка запроса,
- **When** запрос завершается,
- **Then** в лог пишутся метод, путь, статус, длительность.

**AC-COMMON.3 — Swagger**
- **Given** сервис запущен,
- **When** открыт `/swagger/` (или `/docs/`),
- **Then** доступна интерактивная документация всех роутов.

**AC-COMMON.4 — Docker**
- **Given** установлен Docker,
- **When** выполняется `docker-compose up`,
- **Then** поднимаются сервис и все зависимости (БД, Redis, векторная БД).

**AC-COMMON.5 — Отсутствие авторизации**
- **Given** любой запрос,
- **When** он обрабатывается,
- **Then** авторизация не требуется, идентификация — по сессии.
